# Current implementation

`needmark` is an independent MIT-licensed package for Node 22.12+. Its optional Vite plugin supports Vite 7.3.2/8; the local review proxy does not require Vite or React. The annotation UI does not depend on React, hosted NeedBack, an account or an agent connector. It saves ordinary local files for an agent with access to the project. Installing the package does not launch an agent.

Quoted control captions below use the Japanese default; the English setting provides the corresponding localized controls.

## Activation and boundaries

`needmark({ origins, outputDir, capture, language })` registers a Vite plugin only for development serve, excluding preview; every option is optional. NeedMark is switched off when `NEEDMARK` is `0`, `off`, `false` or `no` (case-insensitive, trimmed), or when the config sets `enabled: false` and `NEEDMARK` is not `1`, `on`, `true` or `yes`; a non-boolean `enabled` is rejected. A switched-off plugin stays registered, because Vite chooses plugins before the config is loaded, but adds no server config, API, source annotations or scripts. Without an argument, the plugin loads the project configuration from the current working directory in its `config` hook, with the same loader and legacy fallback as the CLI, so builds and preview never execute it; an explicit argument, even `{}`, skips the file. Each load imports the file again, so a Vite restart in the same process sees edits. Configured origins include scheme and port and match exactly. Without them, any HTTP(S) origin whose hostname is `localhost`, `127.0.0.1` or `[::1]` is allowed regardless of port; the server API, HTML injection, JSX source annotations and the widget all apply the same rule, and the script omits `data-needmark-origins`. AsyncLocalStorage associates each HTML request with its origin. Vite's `transformIndexHtml` adds the script to entry HTML; for a GET from an allowed origin whose HTML a framework renders in its own middleware without that hook (Astro), the plugin appends the same script after the last chunk of a `text/html` 200 or error response with identity encoding, removes its `Content-Length` and does not buffer or parse the stream. A page already handled by `transformIndexHtml` is not appended twice; responses whose headers arrive as raw arrays are left unchanged. Production build and preview do not register the plugin, inject scripts or copy feedback assets. The storage directory must be a dedicated folder outside publicDir and is denied direct Vite static-file access. The client mounts only when its window is the top document. HTML injection into a child response does not create another widget; selecting an accessible same-origin child uses the parent widget. A child URL opened as a top page can mount its own widget.

The shared review API is under Vite's base followed by `/__needmark`, or `/__needmark` on the review proxy. `createReviewApi` validates origins/capture/language preferences, creates one session token and storage instance, supplies script attributes, and handles only its own endpoint prefix; other requests remain with the adapter. Feedback reads and writes require a per-server random token, an allowed Host-derived origin, matching Origin when present, and a fetch site other than cross-site. No CORS endpoints are exposed. PNG payloads are limited to 5 MB; complete requests to 8 MB. UUID identifiers and regular-file checks reject traversal and symlinked item/context/image files.

Users of a trusted shared development server see the same files. Author names are self-reported, and a comment without one shows no author in the widget and `Guest` in prompts while `context.json` keeps it empty; there are no accounts or per-user permissions. Git sharing transfers files between checkouts rather than providing live remote submission. Deployed static staging builds do not run this Vite adapter.

## Local review proxy

`needmark dev [--port=<port>] [--capture=…] [--directory=…] -- <command>` wraps a development command instead. It takes the review port from `--port`, else from `-p <port>`, `--port <port>` or `--port=<port>` in the command (removed before starting it), else `PORT`, else 3000, listens on `http://localhost:<port>` and starts the command with inherited stdio and `PORT` set to a free loopback port, through a shell only on Windows. It waits up to two minutes for that port to accept a TCP connection (trying IPv4 and IPv6), then prints the review URL; a command that exits first or never listens stops the proxy with an error that points to `--target`. SIGINT and SIGTERM are forwarded to the command, the proxy closes when it exits, and its exit code becomes the CLI's. A busy review port fails before the command starts. When NeedMark is switched off ([activation](#activation-and-boundaries)), the command runs unchanged with its own port and no proxy.

`pnpm exec needmark dev --target=http://localhost:3000 --origin=http://localhost:4190` starts a separate proxy around an already running development server. The command loads the current project’s `needmark.config.ts` and adapts its shared language, capture, outputDir, editor, contextAttributes, components, onFeedbackChange and onSubmit settings to the proxy. Explicit capture/directory flags override those values. The application is started independently, and config.origins remains the Vite allowlist rather than a proxy listener setting. The default review origin is `http://localhost:4190`, while target is required. Both URLs must be exact loopback HTTP origins (`localhost`, `127.0.0.1` or `[::1]`), must differ, and the review origin must include a port. `needmark/proxy` also exports `startReviewProxy` with a project-root option and a close method.

The proxy forwards ordinary requests and WebSocket upgrades for development/HMR. It rewrites proxy-origin Origin/Referer headers for the upstream, local redirects back to the review origin, and matching cookie domains. It forwards HTML incrementally and appends the review script to HTTP 200 and error HTML responses, decoding gzip/deflate/Brotli when necessary and removing stale length/ETag headers. It reuses an existing script/CSP nonce when found, without relaxing the application's CSP. Application absolute URLs, HTTPS-only cookies or framework-specific allowed-origin checks can still require application development settings.

Review Host/Origin validation and protected API routes run before forwarding. Feedback paths are blocked from upstream static access; storage must be dedicated and outside the project's `public` folder. Stopping the CLI on SIGINT/SIGTERM closes the proxy and connections. Nothing is imported into the application or installed into its build pipeline, and the command does not publish a server.

The proxy provides DOM/CSS/component context and screenshots without transforming application sources. It enables optional React development source lookup through the protected API. Existing explicit annotations remain usable. Vite's compile-time source mapping and its activation boundaries remain specific to the Vite adapter.

## Connecting the development server

`planConnection` looks for `astro.config.{ts,mts,js,mjs}`, then `vite.config.{ts,mts,js,mjs}`, then a `package.json` `dev` script running `next dev`. A config that already imports `needmark` is reported as connected. Otherwise Babel parses it as a TypeScript/JSX module and MagicString edits it in place: the exported object is found through `export default`, an exported or local constant, a single call argument such as `defineConfig({...})`, or an arrow/function expression whose body or single `return` is an object, unwrapping `satisfies`, `as` and non-null assertions. Vite gets `needmark()` first in an existing `plugins` array, or a new `plugins: [needmark()]` property before the first property; Astro gets the same inside an object `vite` option, or a new `vite: { plugins: [needmark()] }` property. The import is added after the last import, or first. A non-array `plugins`, a non-object `vite`, any other export shape or a parse failure leaves the file untouched and reports manual setup. For Next.js the `dev` script gets the `needmark dev -- ` prefix by replacing its JSON-encoded value in the file text, preserving formatting; an already prefixed script is connected. The plan lists the changed lines, which `init` prints after writing. In a terminal the recommendation includes connecting when an edit is possible, and declining asks for it separately with the effect on the team and how to undo it; without a terminal, only `--connect=yes` writes. `needmark remove` reverses the same patterns: it removes `needmark` import declarations and `needmark()` array elements, removes a `plugins` property that becomes empty (an emptied sole property becomes `{}`), removes an Astro `vite` option whose only property was that `plugins`, and strips the script prefix. Lines that held only removed code are deleted whole. `needmark.config.ts` and feedback are kept, and the CLI prints the package manager's uninstall command.

## Initial setup and preferences

`pnpm exec needmark init` creates `needmark.config.ts` exclusively, refusing to overwrite an existing config. When `needmark.config.ts` already exists, the CLI skips writing settings and Git rules, asks only the connection question (or follows `--connect`) and reports that it kept the file. Its terminal dialogue, output and flag errors are always English. A terminal first shows the recommended settings (review language from the terminal locale, local sharing, DOM capture) with any flag values applied and asks `Use the recommended settings? [Y/n]`; declining asks each remaining choice as a numbered list with a one-line explanation, accepting the number or the flag value and asking again after an unknown answer. `--language=en|ja` and the other flags supply choices noninteractively. Without a terminal the defaults are `ja`, local and DOM. The generated config explains the language and capture values in comments. The generated config has no `origins`, so the loopback default applies. Invalid language values fail before initialization writes a config. The generated config uses `satisfies NeedMarkOptions`. Connecting the development server is a separate, consented step described in [connecting the development server](#connecting-the-development-server); when it is declined or impossible, initializer output lists the manual steps with the project's [package manager](#package-managers) command. The CLI loads project configuration from its current working directory, without searching parent directories. An absent file preserves existing defaults. Jiti loads the trusted TypeScript module on the supported Node versions; the default export must be a non-null settings object. Syntax/import failures and invalid exports fail explicitly. Feedback content is never imported. Configuration changes take effect on the next CLI invocation or proxy restart.

Storage commands use config.outputDir unless a directory is supplied, then fall back to the default feedback folder (`.needmark/feedback` for a new project). Explicit storage directories skip config loading. List, watch, export, resolve, reopen, reply, edit and delete therefore share the server’s configured feedback folder. Export passes the selected directory to the prompt formatter. Help, unknown commands and init do not execute configuration. API callbacks configured in the file run only through the development adapter; direct CLI/file changes retain the existing watch behavior.

Local sharing appends a targeted `/.needmark/` Git ignore rule. Git sharing appends rules that expose only `.needmark/feedback`, preserving existing rules and keeping other NeedMark files ignored. Changing these rules changes what a subsequent Git commit can include; the CLI does not commit or push.

`language` accepts only `en` or `ja` and defaults to `ja` for the widget. The script carries `data-needmark-language`. A valid `needmark-language` browser preference overrides configuration; invalid or unavailable preferences fall back to valid configuration, then `ja`. Capture/author settings include a language selector. Saving it changes the toolbar, forms, list, viewer and known capture-error guidance, and persists the choice for that review origin. Application content, comments, replies, authors and source identifiers are never translated. Unknown server or third-party error text is preserved.

`capture` sets the initial browser method. A saved browser preference takes precedence. Capture method and output detail have an information button next to their label whose tooltip, shown on hover or focus and announced through `aria-describedby`, holds the longer explanation; the other settings show only their label; The settings panel has no header (its title **設定** is visually hidden); its footer has **キャンセル**, which closes it, on the left and **保存** on the right, preceded by **撮影を停止** only while a tab capture stream is active. The first **コメント** starts selection immediately with the configured or saved values; settings open only from **設定**. Browser preferences retain capture method, author, output detail, theme and global keyboard-shortcut enablement across reload; unavailable browser storage does not prevent server saving. OS/light/dark themes, draggable toolbar, pin visibility and animation pause are available. Toolbar dragging starts anywhere on the toolbar, including its buttons, accepts only the primary left pointer and starts moving after three CSS pixels; a drag that starts on a button does not run that button's action, while a press that moves less still clicks it. A completed drag stores finite `{ x, y }` coordinates in `needmark-toolbar-position`. Reload restores them; viewport resize, toolbar resize and reappearance clamp the visible position to a four-pixel margin, without overwriting the stored or chosen position, so the toolbar returns to it once it fits again. Hidden zero-size toolbars defer this correction. Oversized controls keep the handle at a visible origin. Without a saved position, the toolbar stays centred at the bottom; a saved position replaces the centring with exact coordinates. Escape, pointer cancellation, lost capture or viewport resize cancels an active drag, restores its starting styles and releases capture; Escape does not simultaneously close another surface. Clicks and cancelled gestures do not write the preference. Inaccessible browser storage leaves movement usable. Shift+C toggles selection, Shift+P toggles pause, and Shift+H hides/shows controls. Ctrl/Cmd+Shift+F is an alias for Shift+C. The toolbar is a compact icon toolbox centred at the bottom of the viewport: drag handle, then the **コメント** tool (a plus icon), view controls (pin visibility and animation pause), **コメント一覧** with its open count in a 14-pixel badge overlapping the lower right of its icon, **設定**, and **ツールバーをたたむ**. Buttons show icons only and keep their localized accessible names; all widget icons (toolbar, panel back/close, image viewer close/zoom, hint help/end) are filled 40×40 glyphs inlined from the NeedBack console icon set, drawn at 16 pixels everywhere inside fixed square buttons (32 pixels in the toolbar, 28 in the hint and panel headers, 38 for image zoom, 20 for setting explanations) (the comment list uses `nav-open`), with no runtime dependency on NeedBack; the select button is pressed while selection is active, pins/pause expose `aria-pressed`. While the page is paused, the pause button shows a play icon without a background; its accessible name changes to **アニメーションを再開**. Toolbar buttons are 32-pixel square icon buttons; an active tool uses the same light background as hover. **ツールバーをたたむ** collapses the toolbar to the single **ツールバーを広げる** button; the other tools, including an active pause, are hidden until it is expanded, while global shortcuts keep working; the choice persists in `needmark-toolbar-collapsed`. Collapsing never ends a selection, panel or pause. Hovering or focusing a toolbar button shows a tooltip from the review host after a short delay with its name, a one-line description of what it does and, while global shortcuts are enabled, its shortcut; the tooltip stays inside the viewport, is hidden while dragging, during capture and when the pointer leaves, and never takes focus. The shortcut also stays available in the button's `data-shortcut` attribute; no native `title` tooltip is used. Global shortcuts are enabled initially and can be disabled in browser settings; this affects Shift+C/P/H and Ctrl/Cmd+Shift+F. Global shortcuts do not fire inside inputs, textareas, selects, inherited editable content or during IME composition. Ctrl/Cmd+Enter in NeedMark submits only its own comment/edit/reply forms; host forms and shadow-root editors are never submitted or intercepted by this handler. Local Escape, viewer navigation and active multiple-selection controls remain available with global shortcuts disabled. Escape closes the current NeedMark surface without closing a host modal simultaneously.

The review UI follows the NeedBack design tokens: Helvetica/system UI typography, white/gray surfaces with gray borders, NeedBack primary-interactive blue (`#0f4cc0` in light theme, `#9acdff` in dark theme, with white or dark navy `#0a2063` text) for filled primary actions, outline primary actions (interactive border and text, light primary background on hover), the chosen category (interactive border and text on the light primary background), focus rings (shown only after keyboard input, so clicks and the focus the UI moves after them stay unringed; text fields always show their focused border), selection outlines and selected tools; filled hover and pressed states mix 6% and 10% black in light theme and white in dark theme like NeedBack's filled buttons, and NeedBack status colours for errors. Open pins use the NeedBack unread pin colour (`#1965e3`). Panels use 12-pixel corners with the NeedBack panel shadow; the dark theme uses the NeedBack dark tokens. Unless the reviewer prefers reduced motion, panels scale in from the toolbar button or target they open from and fade back toward it; a panel that stays open glides to its next position and height while the next screen slides in from the side it was reached from (a comment from the right, the list from the left), and a capture that arrives later grows the panel instead of making it jump. Search opens out of its header icon, menus grow from their button (upward when the panel has no room below), pins pop in and shrink away when toggled, and Shift+H fades the toolbar. A drag of the toolbar or a panel ends where it was last shown even when the page swallows the pointer release; only Escape puts it back. The review UI lives in an open shadow root. Its host explicitly resets inherited font, letter/word spacing, text transformation, indentation, alignment, direction and whitespace, including host-level application `!important` rules. These resets also apply after moving into a native modal dialog. Its host remains pointer-transparent, while the toolbar, forms and armed selection cover enable their own pointer handling. Intentional control, brand and code typography remains local to the UI; authored content and the application’s styles remain unchanged. Capture-time visibility uses the existing host visibility property; external positioning rules still follow the normal CSS cascade.

## Migration

Existing projects can keep `needback.config.ts`: the CLI reads it only when `needmark.config.ts` is absent, and an invalid NeedMark config stops startup without falling back. Without an explicit `outputDir`, feedback uses `.needmark/feedback`, or existing `.needback/feedback` when the NeedMark feedback directory is absent; when both exist, NeedMark takes precedence. Feedback is never merged, moved or deleted during this selection. `init` refuses to create a config when either config name exists; when only legacy feedback exists, it keeps that output directory and targets it in the Git ignore rules. Browser preferences, and toolbar position read `needmark-*` keys first, then `needback-kit-*` only when the new key is unset; saves use the new keys and leave old keys intact.

## Review interaction

While the selection cover is active and no gesture or panel is open, pointer movement previews the current hit with an outline, its tag, a best-effort name and an available component name. Pressing or releasing Ctrl/Cmd recomputes the hit at the retained pointer position without requiring movement. The preview uses local DOM hints only, without building saved context, reading form value properties or requesting source resolution. Names prefer up to four `aria-labelledby` references, then `aria-label`, up to two associated labels, `alt`, control text, `title` and finally ID. Label text traversal skips form controls and script/style content, visits at most 40 nodes per label and caps displayed names at 160 characters. Component hints use the existing local source-owner or closest runtime component walks, bounded to 40 steps, and are capped at 100 characters. These are bounded hints, not a complete accessibility-name algorithm or a verified source match.

The tooltip is clamped to the viewport and belongs to the existing review host, excluded by DOM capture and hidden with the host during tab capture. Starting a gesture, leaving selection or the cover, window blur and observed page mutations/scroll/resize clear it. A hovered target also follows rendered ancestry (`assignedSlot`, then `parentElement`, then a shadow host or frame owner), bounded to 200 nodes and eight unique document/open-shadow roots, to watch mutations, scrolling, document resize and frame load. This includes shadow-local changes surrounding a slotted leaf. These events clear the preview rather than retain stale target geometry or names. A subsequent pointer movement recreates it. This observation does not guarantee detection of every visual change, such as animation without an observed event.

**コメント** is one tool whose gesture chooses the target: a click selects an element, a drag selects a free area, Shift adds elements to a multiple selection, Ctrl/Cmd+click picks a covered element, and Alt/Option+drag records a partial text range, including inline text and reverse drags within one DOM root. The hint takes the place of the toolbar's buttons while selecting: the toolbar keeps its position, handle and height, eases to the hint's width on a single row (a narrow viewport truncates the hint text before the buttons) and fades the hint in, then returns to its buttons when selection ends; reduced motion switches without animation. The hint is one line (**クリック・ドラッグで選択**, or **N件を選択** in multiple selection) followed by contextual buttons, a **使い方** icon link that opens the getting-started guide's comment section for the current language in a new tab (toolbar dragging captures the pointer on the pressed link, like on a button, so the link keeps its click), and an icon-only **終了** button. These two icons show toolbar tips on hover only (the end button's tip includes Esc), because selection start moves focus to the end button; starting selection also closes any tip that was open or pending for the hidden buttons. Multiple selection is entered only by a Shift gesture; the gesture list lives in the guide so the toolbar fits narrow viewports. Different iframe/shadow roots cannot form one text range. A drag records its starting point in page coordinates, so scrolling during the drag (wheel, keyboard or automatic) extends the rectangle beyond the viewport while its start stays on the same page content. While a free-area or multiple drag holds the pointer within 40 CSS pixels of a viewport edge, the page scrolls toward that edge each frame, faster nearer the edge; Alt/Option text drags do not scroll automatically. During an Alt/Option text drag, the preview highlights the line boxes of the text range that releasing at the current pointer would record, instead of a rectangle; when no text lies under the pointer or the range would cross DOM roots, no highlight is shown. The cover shows a text cursor while Alt/Option is held outside multiple selection and throughout a text drag. The free-area rectangle is saved in viewport coordinates of the release position, so its parts outside the viewport have negative or beyond-viewport coordinates. Multiple selection toggles individual elements on click and adds the meaningful elements whose visible boxes intersect a dragged rectangle with positive area. Boundary-only contact and empty rectangles add nothing and have no center-point fallback. Button/media inline descendants belong to their semantic owner; paragraphs and headings retain inline emphasis. Within each new batch, matched ancestors of other matched semantic elements are removed, and every remaining target is retained. Existing explicit selections are retained, and repeated drags do not toggle them off. The bounded traversal visits at most 5,000 nodes across open shadow roots and accessible same-origin frames, with at most eight root crossings per branch, excludes the NeedMark UI, and reports incomplete search when its node or root budget is reached. This flag remains with the selection through additions and undo; completion saves it as `target.code.truncated`, and the composer and exports warn that discovery is incomplete. Eligibility uses axis-aligned viewport/frame content and applicable overflow clipping with hidden/opacity checks; retained context and capture geometry remain the original full element boxes. Numbered outlines follow the selected originals. Enter or its completion button finishes; Backspace removes the last selected element. Shift+click or Shift+drag enters multiple selection; later plain clicks keep toggling targets until selection completes. Ctrl/Cmd+click also enters multiple selection and opts into deeper hit testing. Alt/Option is ignored during multiple selection. The picker skips the frontmost hit and its ancestor/descendant branch, preferring an independent lower hit inside the frontmost open shadow root or accessible same-origin frame before an outer-root alternative. It scans through additional empty container covers and accessible child roots, rejects invisible or fully clipped candidates, and prefers content-bearing targets. Empty visual candidates fall back to the smallest positive visible area. Content classification uses controls, non-container tags or direct non-whitespace text. The generic containers are `div`, `span`, `section`, `article`, `main`, `aside`, `header`, `footer`, `nav` and `slot`; an ID alone does not make one content-bearing. Deep branch ancestry follows assigned slots with a 200-node bound, without changing selector/source ownership. Lower roots retain meaningful frontmost content, so an inner labelled overlay remains selectable after an outer branch was skipped. This is a hit-stack heuristic rather than certainty about the reviewer’s intent. Root traversal retains the padded/scaled frame transform and eight-level bound. If no lower branch exists, the normal frontmost target remains selected. It never hides or changes application overlays; saved screenshots retain the actual visible screen. Ordinary clicks and Alt/Option text drags keep their frontmost behavior. Ctrl-click suppresses the native context menu only on the active selection cover. Mode, Shift and Ctrl/Cmd are recorded at primary pointer-down, so releasing or pressing modifiers during a gesture does not change its selection type or target depth. Releasing Ctrl/Cmd does not finish selection; Enter or the completion button does. Additional pointers cannot replace or commit that gesture. Pointer cancellation or lost capture clears only that gesture and releases capture; the first Escape during a drag does the same, preserving prior selections, while the next Escape ends selection. Enter and Backspace are ignored during an active multiple gesture, including the first Shift gesture. Explicit multiple selections have no fixed target-count cap. Each selected original keeps its individual context through capture, local save/read and all copy/export paths. HTTP feedback writes retain their existing eight-megabyte body and five-megabyte decoded-PNG limits; a rejected write retains the typed comment for retry.

Selected elements retain their original Node, root, document and bounded element evidence when each selection is added. Validation checks their current document/frame connection, recorded child page URLs, identifiers, text/accessibility name, source evidence and closest known component. When frame URL evidence is present, every recorded iframe must retain its exact URL, including query and fragment; a route change invalidates even a still-connected node with identical text and source. Older records without this optional evidence retain their previous identity checks. It does not resolve a replacement through the old selector. Disconnected, replaced or changed targets are removed with a notice; if no targets remain, selection can restart empty. Source line/column movement, class/style changes and geometry changes alone do not remove a target. Validation remains bounded by captured text/name/attribute evidence: a virtual item reusing the same observed information is indistinguishable. Stable row identifiers can be included through `contextAttributes`. Hidden and offscreen original elements stay selected; image acquisition still has the existing visibility and viewport checks.

An exact URL change ends the selection, including query/hash and history changes. Ending selection, settings, list or details, or hiding controls also ends it. Completing a selection obtains fresh selectors, source context and geometry before the existing capture guard starts. The composer already permits interaction outside its panel.

A composer with no header (its title **コメント** is visually hidden, and **キャンセル** closes it, so it has no close button or drag grip) appears next to the target: the capture (its size in the image tooltip), a status line that appears only while capture is pending or after it fails (**画像を撮影できなかったため、画像なしで保存します。**, with the reason in its tooltip), the **カテゴリ** radio group and the focused comment field, whose accessible name is **コメント本文** and which has no visible label. Target details, source/CSS evidence and copy actions are not shown; the source lookup status is announced to assistive technology only, and saving does not wait for it. While a new composer is open for an element, text, area or multiple selection, a dashed draft outline marks each selected target's recorded rectangle (every original of a multiple selection, otherwise the target rectangle). It belongs to the review host, so DOM capture excludes it and tab capture hides it. Page scroll or viewport resize removes the outline rather than leaving it at stale coordinates; closing, saving or replacing the composer also removes it. The composer and edit form offer **カテゴリ** above the comment as three separated pill radio buttons (the selected one has a primary-interactive border and text): 修正 (`fix`, the default for new comments and for edited items without a category), 相談 (`discuss`) and 質問 (`question`). Every save writes the chosen category. Enter on a category never submits the form. A new composer has a single **保存** button (also Ctrl/Cmd+Enter inside the comment field). It waits for the capture and for the composer to finish growing to fit the preview, so the button does not move under the pointer; a failed capture switches the draft to an image-free save and enables the button without another step. After a successful save it closes the composer, shows a toast centred 20 pixels above the bottom of the viewport (drawn above the toolbar and any panel) and restarts selection instead of opening the list. Every new selection starts with plain clicks selecting single elements; a previous multiple selection does not carry over. A failed save keeps the composer and typed text. List, settings, composer, detail and edit panels share viewport placement. The list is centred horizontally over the **コメント一覧** button and settings over the **設定** button, opening above the toolbar with a twelve-pixel gap; when less than 120 pixels remain above and more space is below, they open below instead. Details open beside their pin after the target has been scrolled into view, twelve pixels to its right (or to its left when the right does not fit) with their top at the pin's top, moved up only as far as needed to stay inside the viewport; without a visible pin (resolved items, hidden pins) they open beside the target's outline, or beside the recorded rectangle shifted by the scroll since capture. Pressing **コメント一覧** while the list is open, or **設定** while settings are open, closes that panel like its close button. Panels fade and scale in over 180 ms and fade out over 120 ms; with reduced motion they appear and disappear instantly. A closing panel is already hidden for keyboard, assistive technology and pointer input while it fades, and opening another panel ends the fade at once instead of showing both. Other panels without a target keep the default placement. When a panel horizontally overlaps the toolbar, it uses the larger space above or below the toolbar with a twelve-pixel gap and a ten-pixel viewport margin. Its maximum height is capped to that space with internal scrolling. If both spaces are under 120 pixels high, the toolbar uses temporary visibility hiding while the panel uses the full viewport interior. Closing the panel or beginning selection restores toolbar visibility before returning focus; the user’s hidden state and saved coordinates remain intact. Every panel's header except those of the new-comment composer and settings (title in 12-pixel semibold) stays pinned to the top of the panel while its body scrolls, separated from the body by a bottom border, and is the panel's drag grip: a primary press on the header outside its buttons (which keep their clicks) moves the panel after three pixels, Escape during a drag puts it back without closing it, and pointer capture is held by the panel so a list refresh mid-drag does not end it. The dropped point is kept across list and details until the panel closes, is not saved, and is only clamped inside the ten-pixel viewport margin, so growing content or a smaller window never hides it. Panel/toolbar size changes, toolbar movement and cancellation, and viewport resize recalculate styles without rebuilding forms, moving application targets, changing focus or replacing copy selections. Source/image content changes use the same size observer. Native capture’s host visibility hiding does not change these measurements. Page exit disposes observers, resize listeners and pending animation frames. DOM capture runs while text is entered; native capture briefly hides controls to obtain clean pixels. Saving waits for an image, or saves without one after capture fails. Switching panels and selection/hide shortcuts preserve unsaved comment/edit/reply text by requiring save or cancellation. Failed writes retain input for retry. Successful writes update the UI from the returned feedback, so a subsequent list read failure does not turn a saved reply or reason into a retryable submission. Async completions do not reopen a closed panel or replace a newer surface.

The existing UI host uses a transparent manual popover where supported and moves inside an active document-level native modal dialog. This keeps controls above the dialog and within its focus boundary while preserving the same shadow UI and drafts. Pins outside the active native modal, or attached to currently hidden elements such as closed dialogs, are hidden. Nested document dialogs and returning to the page are supported; dialogs inside shadow roots and custom focus-trap behavior are not covered by this adapter.

Pins show unresolved feedback for the exact pathname, query and hash. Pins whose current element target can be identified use the positive axis-aligned intersection of the current full element box with the page viewport, accessible same-origin frame viewports and applicable ancestor overflow/paint clips. Fully clipped, known hidden or unavailable bounded paths hide that pin. Partial targets place the pin within the remaining visible rectangle, including after collision offsets and viewport placement; the marker itself can extend beyond a narrow visible portion. This calculation follows at most 200 composed ancestors and eight non-page document/open-shadow roots, including assigned slots where accessible, without scanning unrelated page nodes. ## Code identification

The dev plugin parses Vite entry HTML before Vite processing using parse5 and local `.jsx`/`.tsx` before ordinary JSX compilation using Babel parser. MagicString preserves original source maps. Native tags receive `data-needmark-source` with a working-directory-relative file and one-based line/column, plus the named enclosing JSX component when available. Custom component calls are not annotated. Explicit annotations remain intact. JSX values are guarded by allowed origin; dev modules contain the guard on all origins. HTML metadata is injected only on allowed origins. Production/preview, SSR transforms, dependencies and files outside Vite root are skipped. Unsupported syntax falls through without breaking the app.

At selection time, `target.code` records every original in an ordinary multiple selection, or a sample of at most 12 elements for area/text context, with selector, visible text, identifiers excluding input values, best-effort accessibility name, nearby headings, selected computed CSS, runtime React ownership when available, rectangle and source. Direct positions are `self`; mapped parent positions are `ancestor` hints. Runtime React ownership is read without importing React. A direct compile-time annotation takes precedence over optional runtime lookup.

`contextAttributes` accepts up to six distinct additional lowercase HTML attribute names (100 characters each), after removing defaults and duplicates. The 14 default names remain enabled; storage accepts at most 20 captured attributes, with whole values of at most 500 characters. New captures omit longer values instead of truncating them. Selector construction and current-source validation use the same value bound; selectors still keep their existing 2,000-character storage limit. Configuration rejects `value`, `style`, `nonce`, `srcdoc`, names starting with `on`, and `data-needmark*`/`data-needback*`. The Node adapter validates configuration and sends only the normalized names as a script attribute. The single widget configures its context collector once, covering element/multiple/area/text selections without modifying application attributes. Empty custom attributes are retained. Restoring a recorded custom identifier compares its recorded value even after the current configuration changes; a changed or missing custom attribute rejects the match. The proxy passes the validated additional names into its source resolver. Only these configured names expand source verification; request-supplied attribute names cannot expand the server allowlist.

The proxy's protected `POST /__needmark/source` accepts up to twelve aligned element tags and their attributes and up to five development creation frames per element, with a 128 KB request limit. The widget extracts these transient frames from the selected React host's own creation stack, accepting bounded V8 and JavaScriptCore HTTP(S) frames; raw stacks and frames never become feedback fields. JavaScriptCore can omit a user frame during tail-call optimization. Missing creation evidence leaves DOM/component information usable and is never replaced by a parent's creation stack. Lookup runs alongside comment entry. Multiple contexts are processed in sequential twelve-target batches with one seven-second client deadline. Batches without creation frames are skipped; a failed batch leaves its targets intact and does not discard a later successful batch. Each response is aligned to its original context offset and rechecks current target identity before adding source evidence. Saving ordinary commented feedback before it completes retains all DOM context and any completed source evidence without waiting. Cancelled, stale, changed-target and saving-time responses do not replace the current draft.

The resolver reads JavaScript assets and declared source maps only from the fixed local upstream, accepts configured local origins and does not follow redirects. A request shares one five-second deadline and deduplicates asset/file reads only within that request. JavaScript assets are limited to 4 MB, maps to 8 MB and current project source to 1 MB. Resolved source files must be regular JavaScript/TypeScript files within the real project root, outside hidden paths, dependencies, build directories and feedback storage. A directory or special file is not a file candidate.

Source maps identify a candidate file, not a trustworthy current line. The resolver parses the current file and returns an exact location only for a uniquely matching native JSX tag with literal `id`, `data-testid`, `data-test`, `data-qa`, `data-cy`, `data-component` or configured additional attribute evidence. Competing dynamic/spread identifiers, multiple matches or a known component-name mismatch produce a file hint. A changed line number is obtained from the current AST. The first mapped project file remains the candidate; an ancestor frame does not silently promote a hint to an exact element location.

A verified runtime position uses `source`, `sourceRelation: "self"` and `sourceOrigin: "runtime"`; UI, Markdown and prompts label it as current JSX verified by identifiers. A `sourceHint` contains only a file and optional component name and is labelled as a file search hint, with no invented line/column. Failure or unavailable metadata leaves DOM/component evidence usable. New comments and subsequent mutations retain only defined context fields, excluding transient lookup frames.

Area sampling keeps semantic text blocks including inline children, controls and media whose visible overlap with the selected region covers at least half their original full area. It uses the same bounded page/frame/ancestor clipping calculation as element pins, while retaining full element rectangles and the authored selection region. It suppresses redundant descendants, scans up to 5000 nodes and marks truncation. If no sample matches, the native center-point hit supplies the existing fallback context. Text ranges record semantic owners. Open shadow roots and same-origin frames retain ordered root paths and top-page viewport rectangles. A complete, readable root walk of at most eight crossings also records `frameUrls`, one exact child URL per iframe entry, from outer to inner; shadow entries consume no URL slot. Partial or unreadable walks omit URL evidence. Present URL evidence must contain at most eight nonempty absolute URLs, each at most 4,096 characters, with exactly the iframe count of the root path. HTTP(S), about:blank/about:srcdoc with their query/fragment, and HTTP(S) blob URLs from the parent page origin are accepted as metadata only; they do not authorize any fetch. Saved element-pin matching checks these URLs before element/source evidence, so an identical element on a different child route remains unconfirmed. Same-origin iframe coordinates use the content-box origin, including CSS padding and borders, with positive axis-aligned scaling. Element/range positions and pointer/caret inverses share this mapping; marquee eligibility and pin clipping use the current child viewport. Closed roots and cross-origin frame interiors remain host evidence; rotated/skewed frame geometry is not accurately mapped. Accessibility names are hints from labels/ARIA/alt/title/control text rather than a full accessibility-tree computation.

Selectors first prefer a nonempty identifying attribute that uniquely matches in the selected document or shadow root, retaining `id` and `data-testid` precedence. The same six built-in identifying names and configured additional names are used for current selection and runtime source verification. Otherwise selectors grow to find a unique bounded path; ambiguous selectors are rejected. Restoring a recorded element compares its tag, strong identifiers, text/name and source evidence. Runtime-verified targets additionally require a live unique strong identifier and matching closest component evidence; saved additional identifiers remain eligible after current capture configuration changes. Truncated values cannot independently establish this live unique identity; contradictory current direct file/component annotations reject a match, while source line drift alone does not invalidate their identity. File hints do not establish element identity. A mismatch uses the recorded location and is labelled stale rather than silently choosing another element. Identical replacements with identical recorded evidence cannot be distinguished.

Vite's annotations do not automatically map Vue/Svelte templates, JSX in `.js`/`.ts`, SSR transforms, dependencies, generated DOM or CSS declaration files. Proxy lookup requires compatible React development host metadata and a usable local source map; it does not guarantee mapping for other frameworks or every server component. DOM context still assists code search when mapping is unavailable. Saved source coordinates can shift after edits. Framework-independent UI does not imply universal source mapping.

## Local editor links

Optional `editor: "vscode" | "cursor"` in Vite/proxy options or the CLI project configuration enables local editor links. Details prepare the links as soon as they open and allow retry after failure. Every rendered location binds its own file and coordinates; an ancestor annotation and a runtime file hint can link to different files on the same element. A file-only hint opens line 1, column 1, without implying an exact target position. Async results require the same panel and connected control and never take focus from a reply or application input. The browser opens the configured application's protocol only when the user clicks the prepared link.

Protected `POST /__needmark/editor` accepts exactly `{ file, line, column }`, with an 8 KB body limit. It uses the existing Host/Origin/fetch-site/session-token checks. Unconfigured editor routes return 404. Vite resolves its recorded paths from the process working directory; the proxy resolves from its project root. Both constrain the real file to the project root and exclude hidden paths, dependencies/build output, secret/private directories and feedback storage, including aliases. Files must be regular supported source files of at most 1 MB; directories, special files and external symlinks are rejected. Lines/UTF-16 columns are one-based positive integers bounded to 1,000,000 and the current file's text. Coordinates that are still in range are recorded positions, not fresh target identification.

The endpoint returns only a correctly encoded `vscode://file/...:line:column` or `cursor://file/...:line:column` URL. A path's query, fragment and colon characters remain encoded as path text. Neither the server nor feedback content executes a shell command or launches a process. The browser/OS may ask before opening the installed protocol handler. The CLI `dev` command uses the editor setting loaded from the project configuration.


## Capture

The default `dom` method uses html2canvas-pro. When the target rectangle lies inside the viewport, it renders the visible viewport. When any part of the target lies outside the viewport, it renders a page region instead: the whole target plus a 48-CSS-pixel margin, at least the viewport's size, centred on the target and clamped to the document's scrollable area, so a tall element, range or multiple selection that was scrolled while selecting appears in full. Scaling never exceeds the device pixel ratio and keeps each dimension within 8192 pixels and the whole image within 2560 × 2560 pixels of area. The pinned renderer handles basic polygon, inset, circle and ellipse clip paths and propagates clipping to descendants; SVG URL clip paths and other unsupported CSS remain subject to its rendering limits. It requires no screen-sharing picker. Lazy images are made eager and smooth scrolling is disabled in the clone. Document-native modal dialogs regain their modal state and recorded viewport box in the clone, keeping targets aligned. Browser-native backdrops and unsupported CSS may still differ from tab pixels. Cross-origin images without CORS, inaccessible frame content, video frames and unsupported CSS may be absent or differ from rendered pixels.

Accessible same-origin iframe documents are rendered recursively at their own recorded viewport and scroll, using their current DOM. Original iframe elements are excluded before renderer cloning, so their `src` or `srcdoc` is not replayed. Their snapshots are inserted as image backgrounds in blank sandboxed clone iframes, retaining the iframe tag, computed CSS box and verified sibling position. The renderer receives clone content rather than the original child document. This preserves current React and edited text state within the renderer’s existing CSS limits; it does not guarantee arbitrary transformed-frame or browser-native effects. The traversal permits at most 64 iframe elements and eight iframe levels, with at most eight open shadow crossings per frame location. Ambiguous clone locations, unavailable insertion positions, non-normal iframe background blending or failed clone loads reject the image. Frame membership, document/URL, child viewport/scroll, geometry and computed-style changes during acquisition also reject it. The original frame DOM, attributes and scroll are left unchanged. NeedMark hosts and sensitive elements are excluded from each child render. Top-page outline and sensitive-region mask positions use the same padded/bordered frame mapping; saved privacy masks retain the existing final-image checks. Inaccessible cross-origin or sandbox-isolated frames retain their outer box without interior pixels.

Explicit `tab` mode uses getDisplayMedia and requires the browser's permission to share the current tab. Window/monitor sources are rejected; Capture Handle checks the selected tab when supported. Where that facility is unavailable, the user must choose the current tab. An active stream is reused until stopped or page exit. Starting can be cancelled even while a browser picker is pending; any late stream is stopped. Switching to DOM is explicit; there is no silent substitution after a tab failure.

Tab capture records only the visible tab, so parts of a target outside the viewport are absent from its image. Controls are hidden before fresh frames are read. Chromium uses ImageCapture.grabFrame; other browsers read the playing video. Resolution requests target DPR, capped at 4096 per dimension. PNG dimensions preserve the returned frame; the target outline (a white halo under a NeedBack blue `#1965e3` line, matching the on-screen selection outline) maps from viewport CSS coordinates, offset by the rendered page region in DOM capture. A text target is marked instead by a translucent fill of the same blue over each line box of its range, measured with the snapshot, matching the drag preview. Privacy masks are opaque fills in NeedBack's inverse surface colour (`#2e3134`). Video color conversion, actual browser constraints and frame timing apply. A capture snapshot records URL, viewport/scroll/DPR, time, target rectangle and captured-context rectangles immediately before DOM cloning, or after the tab-control hiding delay and before frame acquisition. Rendering, the page region and annotation scaling use that viewport. Before accepting the image, the widget verifies the URL/viewport and original target identities, including recorded child routes, and rectangles, with a 0.5 CSS-pixel geometry tolerance. Only accepted images commit the snapshot target/context rectangles, viewport and capture time together. Source, computed-style and identifier evidence retains its selection-time meaning and asynchronous source enrichment; geometry updates do not replace those context objects. Transient original nodes, ranges and capture snapshots never become feedback fields. Cancellation releases bitmap resources and an explicitly stopped stream is not reactivated by a late request.

Saved pixels mask password inputs and `[data-needmark-redact]` regions in the document, open shadows and accessible same-origin frames. The existing `data-needback-redact` attribute is also recognized for image redaction. DOM cloning hides these nodes without changing their layout. Cross-origin interiors and closed roots cannot be inspected; marking their host/iframe explicitly masks the entire region. Masks use sensitive-node identities and rectangles recorded before pixel acquisition, padded by one CSS pixel and rounded outwards to cover accepted subpixel differences. Added, removed, replaced or moved sensitive regions beyond the geometry tolerance during acquisition reject the image rather than masking its old pixels at a newer location. This does not remove sensitive data from the original page or browser's live sharing stream.

Fresh element and multiple-selection captures require all originally selected nodes, with their original identity and closest component evidence when available. The same original nodes may move before acquisition, including outside the viewport; their target/context rectangles are measured again at the snapshot. Replacement, disappearance or movement during acquisition rejects the image. A text capture retains the original range endpoints, offsets, root and complete selected text, including text beyond the stored display-text limit; its target remains the partial range, while owner context retains full element rectangles. Fixed areas keep their authored geometry and validate the bounded existing-context sample without retargeting to its union. Empty geometric areas remain valid. Pre/post checks do not prove stability between samples or correct every DOM renderer discrepancy.

`none` mode saves comments and target context with capture dimensions 0×0 and no image file. Capture failure, including target/viewport/sensitive-region drift, switches the draft to that mode while keeping typed text, so the comment saves without an image. There is no audio/video recording.

## Files and mutation

Each new comment is written into a temporary folder and renamed into a UUID directory:

- `comment.md`: blockquoted comment/replies, author, URL, source context, capture details and optional image reference.
- `context.json`: version 1, IDs/timestamps, comment, author, status, URL/title, viewport/scroll, target context, capture method/dimensions, optional image and replies. Element context may include a verified runtime source origin, a file-only source hint and validated `frameUrls`; raw source-lookup frames are excluded. Child URL evidence is retained recursively for composed targets and included in readable Markdown, all prompt detail levels and target-specific selector/source/component/attribute/style copies. Aggregated context copies keep otherwise identical selectors from different child pages separate. Version-1 records without the optional field remain readable.
- `screenshot.png`: present only for DOM/tab captures.

Ordinary feedback may carry optional `category` (`fix`, `discuss`, `question`); an absent category is treated as `fix`. References reject a category on saving and reading. Files written before this set load with `change` read as `fix`, `approve` read as `discuss` (`change` requested a code change; `approve` requested none) and any `severity` dropped; writes accept only the current values, and a later rewrite stores the normalized record. The category appears in readable Markdown, MCP summaries and every prompt detail level, and as a tag above the comment on list cards and details, including the default `fix`. Statuses are open (未対応) and resolved (解決済み); any other saved status makes the file invalid. Edits retain original creation/capture time, image and target, add updatedAt, and regenerate readable Markdown. Replies have UUID, author, text and timestamps and can be edited/deleted. Old version-1 files remain readable. JSON is the status source of truth. Each context/Markdown replacement is atomic; they are two files, not one filesystem transaction.

Reference saving is an explicit separate action in the composer. It waits for capture readiness, source lookup completion, a blank comment and usable metadata. Ordinary commented feedback can still save before lookup finishes. The comment textarea is readonly during a reference POST and restored after failure only for the same connected draft/view. Duplicate saves and late completion do not replace another panel.

Target references use optional `intent: "reference"` with `comment: ""`; absent intent denotes ordinary feedback. The widget no longer creates references; the API still accepts them and existing ones remain readable. Defined unknown intents, nonblank reference comments and targets without usable recorded identity are rejected on saving and reading. A nonblank target/element selector, source/file hint, component or safe nonblank attribute qualifies; coordinates, tag, text and styles alone do not. References retain UUID, capture/source context, optional image, status and replies. Every reference comment patch is rejected after a fresh locked read, and intent cannot be patched. Notes use replies. Readable Markdown marks the item as a target reference with no change requested. Legacy ordinary feedback remains readable; older readers that require nonblank comments reject new reference records and can fail a mixed directory. Historical truncated attributes are not confirmed by a prefix match against a longer current value.

Per-item filesystem mutexes serialize simultaneous API/CLI updates with a bounded two-second wait. Locks release after normal success/failure. Abrupt process termination can leave an empty `.lock-UUID` directory, requiring its removal after confirming that process has stopped. Deleted items are renamed out of the list before removal.

The protected API supports collection GET/POST/DELETE, individual GET/PATCH/DELETE, image GET and reply POST/PATCH/DELETE. PATCH accepts a nonempty subset of comment/author/status/category. Reply PATCH accepts only `comment`, so the reply keeps its author. `category` accepts its enum values or `null` to remove it; references reject it. Replies are capped at 200 per item; comments/replies at 10,000 characters and authors at 100.

Collection DELETE requires exactly `{ scope: "all" }` or `{ scope: "url", url }`. URL deletion requires an HTTP(S) URL on a configured origin and matches the normalized complete URL, including query and hash. It takes a snapshot of UUID entries and removes each matching item with its image and replies. Invalid scopes are rejected before deletion. Success returns HTTP 200 with `deleted` IDs and an empty `failed` array; individual failures return HTTP 207 with both successful IDs and `{ id, error }` failures. Unreadable or unsafe entries are retained and reported, while other items are still processed. A missing context file is not mistaken for an entirely deleted item. New entries created after the snapshot belong to the next clear.

## Agents and CLI

`list` and `watch` keep their machine-readable JSON unchanged. CLI help is bilingual and does not load project configuration. Commands that already load project settings use its language for their own messages; an explicit feedback directory bypasses config loading as before.

`list` emits complete JSON with file paths. `export` and the widget share one browser-safe prompt formatter with compact/standard/detailed/forensic detail; standard remains the default. The widget stores the selected detail per browser origin and uses it for full-prompt copying and optional submission. An unsupported stored value falls back to standard. The widget uses its selected language for AI instruction prose in both copying and submission. CLI `export` uses an explicit config language; without one, or with an explicit directory that bypasses config loading, it preserves the English formatter default. Technical metadata labels, enum values and commands remain English; quoted user text remains verbatim. Prompt language does not become saved feedback metadata. Prompts directly include comment/reply text, URL, selectors, source positions and local context/optional image paths; the existing three levels also include the readable Markdown path. Compact keeps complete quoted comments and replies, feedback IDs/status/URLs, target selection text, selector/root/source evidence classifications and closest component hints. It omits inline attributes, computed CSS, nearby headings, full ownership chains, authors/timestamps and per-item CLI instructions. Repeated composed top-level code evidence already included in a change is not printed twice. Compact output does not alter saved metadata, images or statuses; full evidence remains available in local files. Comments are explicitly untrusted review data. Every detail level's header tells the agent to follow the project's design rules by reusing existing design tokens, CSS variables and components instead of hard-coded values, and to reply to the comment rather than break those rules when a request conflicts with them; the prompt names no rule files and copies no token values. Runtime positions are labelled as current JSX verified by identifiers; source file hints are explicitly candidates without positions. Standard also includes the closest runtime component hint when source coordinates are absent. This is a code-search hint, not a fabricated file/line. Detailed adds attributes/headings/components; forensic adds CSS, rectangles, viewport and capture details. References and resolved feedback are excluded before every repair prompt detail branch. Reference-only exports return neutral text with no repair header, lifecycle commands, record IDs or local evidence paths. Every detail level prints a `Category` line for items that have one. When a repair prompt contains `discuss` or `question` items, its header tells the agent that they ask for an answer rather than a code change: reply to the comment and leave the code unchanged, while items without a category or with `fix` are change requests; items keep their saved order.

`resolve`, `reopen`, `reply`, `edit` and `delete` mutate local files. `watch` emits an initial JSON snapshot then created/updated/deleted JSON lines at one-second polling and exits cleanly on SIGINT/SIGTERM. Agents can use files/CLI without a mandatory MCP server or a specific provider.

Repair prompts instruct agents to reply with their changes and verification and to leave the item open until the user checks it; standard and longer prompts give the `needmark reply` and `needmark resolve` commands for each item. Image understanding requires an image-capable agent. Vite/source paths are relative to the process working directory; agents should operate from that project. Git sharing does not execute comments or automatically run repairs.

### Package managers

NeedMark installs and runs with npm, Yarn (classic and Plug'n'Play) and pnpm. Commands that NeedMark writes for a person or agent to run, the proxy command in `init` output and the per-item `reply`/`resolve` commands in standard and longer prompts, use the runner of the project that owns the feedback. The nearest of `pnpm-lock.yaml`, `yarn.lock` or `package-lock.json` in the feedback directory (the working directory for `init`) or one of its parents selects `pnpm exec needmark`, `yarn needmark` or `npx needmark`; a folder holding several lockfiles prefers that order. Without a lockfile the command is `npx needmark`. The widget receives the server's command with the feedback list, so copied, exported, MCP and submitted prompts agree.

## MCP server

`needmark mcp [directory]` runs an optional Model Context Protocol server over stdio for agents that support local MCP servers, such as Claude Code, Codex and Gemini CLI. It is part of the CLI and adds no runtime dependency. It resolves the feedback directory like the other storage commands (explicit directory, else `outputDir` from `needmark.config.ts`, else the default folder) and uses the project's explicit language for prompt prose. It speaks newline-delimited JSON-RPC 2.0, answers `initialize`, `ping`, `tools/list` and `tools/call`, and writes nothing but protocol messages to stdout. It does not open a network port, start the review UI or launch a browser.

| Tool | Behavior |
| --- | --- |
| `needmark_list_feedback` | Summaries (ID, status, category, comment, page, target, reply count, file paths). `status` is `open` (default), `resolved` or `all`; references are excluded unless `includeReferences` is true. |
| `needmark_get_feedback` | The complete saved record and its file paths as JSON text, plus the screenshot as PNG image content when present and `includeImage` is not false. |
| `needmark_reply` | Adds a reply; a missing or blank `author` becomes `Agent`, as in `needmark reply`. |
| `needmark_resolve` | Adds the optional `summary` as a reply, then sets `resolved`. Its description asks agents to resolve only after the reviewer confirmed the result or explicitly asked for resolution. |
| `needmark_watch` | Blocks until ordinary open feedback is created, or existing open feedback changes, after the call started; then waits `batchSeconds` (default 3, at most 60) to collect more and returns the batch. Returns an empty batch with `timedOut: true` after `timeoutSeconds` (default 300, at most 3600). Polls files once per second, so CLI, Git and browser changes are all seen. |
| `needmark_export_prompt` | The shared repair prompt for the given `ids`, or for every open repair item, at the requested detail (standard by default). |

Tool errors (unknown ID, invalid arguments, lock timeout) are returned as tool results with `isError: true`; malformed JSON-RPC receives a JSON-RPC error. A request cancelled with `notifications/cancelled` receives no response. When standard input ends, a pending `needmark_watch` returns early with `cancelled: true`, every other in-flight call still finishes and replies, and the process exits after those replies are written. Mutations use the same validation, locks, Markdown regeneration and history rules as the CLI. Like other CLI changes, they do not invoke the development server's `onFeedbackChange`. Saved text is review data inside tool results, not instructions to the agent.

Field correspondence with Agentation's Annotation Format Schema: `category` ↔ `intent`, `replies` ↔ `thread`, `target.selector` ↔ `elementPath`. NeedMark does not emit AFS objects or implement Agentation's tool names, session model or HTTP server.

## Optional Node integration hooks

`NeedMarkOptions` and `ReviewProxyOptions` accept optional `onFeedbackChange` and `onSubmit` callbacks; public payload types are exported from the package entry point. A submission may carry optional `language: 'en' | 'ja'` alongside its prompt; the API rejects unsupported language values. It uses that browser choice, then explicit config language, then the formatter's English default. This optional metadata is passed to `onSubmit` and is not written into feedback records. These functions run in the development server, not the reviewed application or browser. The CLI `needmark dev` command loads these callbacks from `needmark.config.ts`; programmatic `startReviewProxy` accepts them directly.

`onFeedbackChange` receives `directory` and a discriminated event: `created`/`updated` include the saved `feedback`, `deleted` includes `id`, and `cleared` includes `FeedbackClearResult`. Reference creation/updates retain their explicit intent in these events; callbacks that trigger repairs must check it. Comment/author/status and reply mutations produce `updated`; bulk deletion emits one `cleared` result, including individual failures in an HTTP 207 operation. The hook runs after successful storage work with a separate cloned payload and is not awaited by the mutation response. Synchronous throws, asynchronous rejections and logging failures cannot convert a saved mutation into a failed request. Failures are logged server-side. Delivery is best effort without ordering, retries or replay; CLI/Git/direct filesystem changes do not invoke this API hook. `needmark watch` remains the interface for observing those changes.

A configured `onSubmit` adds only `data-needmark-submit="true"` to the widget attributes and enables protected `POST /__needmark/submit` (under the configured Vite base when present). The route has the existing Host/Origin/fetch-site/token boundary. It accepts `{ ids, detail, language? }`: 1–1000 distinct UUIDs, a 64 KB body limit, compact/standard/detailed/forensic detail and optional `en`/`ja` language. Browser-supplied feedback text, paths, image contents, callbacks or destinations are rejected. An unconfigured route returns 404.

The server validates and reads every selected item from current disk before invoking the handler once. Missing or invalid files fail the request before delivery. References and closed items are skipped; a selection containing no eligible repair request returns 400 without invoking the handler. `onSubmit` receives a cloned `{ feedback, prompt, directory, detail, language? }`, with the shared formatter generating the prompt and local context/Markdown/image paths. The handler is awaited. Success returns `{ submitted: string[], skipped: string[] }`; a thrown/rejected handler returns HTTP 502 with a generic error while the detailed exception remains in server logs. Successful or failed handoff does not itself change any comment, image, reply or status.

Submission is explicit and does not queue, retry, upload screenshots or launch an agent automatically. Handler completion means handoff completion, not repair completion. Integrations supply their own timeout and deduplication where needed; an external side effect followed by a rejected handler can make a manual retry deliver again. A receiver needs access to the local image paths or its own upload implementation. Comment/DOM content remains untrusted review data even inside callbacks.

## Animation pause

Pause suppresses CSS animations (including pseudo-elements and newly added document elements) and transitions in the application document while keeping the NeedMark shadow UI active. It also pauses running document WAAPI animations and videos, and resumes only those it paused; already-paused media/animations are not started. Transition suppression is not an exact rewind of a transition frame. The CSS rule does not guarantee coverage inside application shadow trees or other frames.

Function callbacks scheduled through this document's patched `setTimeout`, `setInterval` and `requestAnimationFrame` globals after widget startup stop while paused. Native timer IDs remain cancelable, including timeouts that matured while paused, using either timer-clear API. Overdue one-shot callbacks resume at most one per sixteen milliseconds; missed interval ticks are dropped, and resumed animation frames receive current timestamps. Another pause retains queued work, and a thrown callback cannot strand the remaining queue. NeedMark controls, polling, source lookup and capture use original timer functions and continue working. The browser build injects native timer bindings into NeedMark's bundle, including capture-library polling/image waits; application bundles still use the document's patched globals. The transparent timer wrappers stay installed for the document lifetime so the original queued IDs remain cancelable. Pagehide resumes and cleans the freeze state.

Callbacks scheduled before installation, code holding cached native functions, string timer handlers, other documents/frames, worker/network events and newly created WAAPI/video playback are outside this timer freeze. Pause is a review aid, not a full browser or application suspension.
