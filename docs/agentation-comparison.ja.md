# Agentation との比較とプロダクト評価

[ドキュメント一覧](README.md) · [アーキテクチャ](architecture.md)

NeedMark のベンチマークは [Agentation](https://www.agentation.com/)（v3.1.2、2026-09-21 時点の公開ドキュメント）です。このページでは、両者の仕様比較、NeedMark の現状評価、残っている課題をまとめます。動画の録画は対象外です。差分を埋めたり新しく見つけたりしたら、このページを更新してください（手順は [AGENTS.md](../AGENTS.md)）。

## 1. Agentation の仕様（要約）

| 領域 | Agentation の仕様 |
| --- | --- |
| 導入 | React 18 以上のコンポーネント `<Agentation />`。デスクトップブラウザのみ |
| 注釈モード | テキスト選択、要素クリック、複数選択（Cmd/Ctrl+Shift+クリック、ドラッグ）、範囲、アニメーション一時停止 |
| ツールバー | 一時停止、マーカー表示切替、コピー、全消去、送信（Webhook 設定時）、レイアウトモード、設定。ドラッグで移動、位置を保存 |
| マーカー | ホバーで内容を表示、クリックで編集（設定で削除にも変更可）。単体はアクセント色、複数・範囲は緑 |
| 識別 | テキスト名つきの要素名、CSS セレクタ、React コンポーネント階層、ソースのファイル・行（Vite / Next.js / Webpack / Turbopack） |
| 出力 | Markdown を Compact / Standard / Detailed / Forensic の4段階で出力。`copyFormat` でソースパス・クラス・属性値だけのコピーも可能 |
| 分類 | `intent`（fix / change / question / approve）、`severity`（blocking / important / suggestion）を AFS 1.1 で定義 |
| ライフサイクル | pending → acknowledged → resolved / dismissed（理由つき）、スレッド返信 |
| AI 連携 | MCP サーバー（9ツール：セッション一覧・取得、未対応一覧、acknowledge、resolve（要約つき）、dismiss、reply、watch）。watch によるハンズフリー運用、批評モード、自動修正モード |
| 外部連携 | Webhook（追加・更新・削除・消去・送信）、コールバック API |
| ショートカット | Cmd/Ctrl+Shift+F で起動。ツールバー表示中は L（レイアウト）・P・H・C（コピー）・S（送信）・X（全消去）・Esc |
| 設定 | 出力詳細度、React 検出、マーカー色、コピー・送信時の自動消去、ページ操作のブロック、一時非表示 |
| 保存 | ブラウザの localStorage（7日で消去）。共有には MCP サーバーが必要 |
| 制約 | スクリーンショットなし（テキストのみ）、React 必須 |

## 2. 機能比較

凡例：◎ NeedMark が優位 / ○ 同等 / △ 一部不足 / ✕ 未対応 / － 対象外

| 機能 | NeedMark | 状態 | 補足 |
| --- | --- | --- | --- |
| 要素・テキスト・範囲・複数選択 | 対応。複数選択は件数上限なし、選択途中でページ操作も可能 | ◎ | |
| 奥の要素の選択（Ctrl/Cmd+クリック） | 対応。開いた Shadow root と同一オリジン iframe も対象 | ○ | |
| ホバープレビュー | タグ・名前・コンポーネント | ○ | |
| ソース位置 | Vite はコンパイル時に付与、Next.js 等はプロキシ経由で実行時に検証 | ○ | |
| スクリーンショット | DOM 撮影・タブ撮影・画像なしから選択。パスワード等をマスク | ◎ | Agentation はテキストのみ |
| 保存先 | プロジェクト内のファイル。Git で共有可能 | ◎ | Agentation は 7 日で消える localStorage |
| フレームワーク | React 不要。Vite プラグインまたは開発サーバー用プロキシ | ◎ | |
| 出力の 4 段階 | 対応（compact / standard / detailed / forensic） | ○ | |
| 部分コピー | セレクタ・ソース・コンポーネント・クラス・属性・CSS を個別にコピー | ○ | |
| レイアウトモード | なし（2026-10-08 に機能から外した） | × | コメントの道具に絞る |
| アニメーション一時停止 | CSS・WAAPI・動画・タイマー | ○ | |
| ステータス・返信 | 対応（open / resolved の2値）。却下理由の履歴は持たず、返信で残す | ○ | |
| 対象情報だけの保存 | 対応（コメントなしの参照） | ○ | |
| 日本語 UI | 対応 | ◎ | |
| カテゴリの分類 | カテゴリ（修正・相談・質問、既定は修正）を保存し、Markdown・AI 向け指示に反映。相談と質問はコードを変えず返信で答えるよう指示。重要度は持たない | ○ | |
| MCP サーバー | `needmark mcp` で一覧・取得（画像つき）・返信・解決・待ち受け・指示文の作成 | ◎ | 画像を MCP で直接渡せる |
| ハンズフリー運用 | `needmark_watch` と手順書（[はじめに](getting-started.ja.md#aiエージェントと連携する)） | ○ | |
| 起動ショートカット | Ctrl/Cmd+Shift+F、Shift+C/P/H | ○ | Agentation の単キー操作は、ページ側の入力と衝突しやすいため Shift つきにしている |
| 連続したコメント | 「保存」（Ctrl/Cmd+Enter）で一覧を開かずに次の選択へ戻る | ○ | |
| 初回すぐに開始 | 初回の設定画面に「既定のまま始める」 | ○ | |
| ツールバーの見た目 | 画面下部中央の、たためるアイコンのツールボックス。ツールチップに名前・目的・ショートカット。配色は NeedBack のブランドトークン | ◎ | |
| 入力中の対象表示 | コメント入力中も対象の枠を表示 | ○ | |
| Webhook | Node のコールバック（`onFeedbackChange` / `onSubmit`）で代替 | △ | URL を指定するだけの Webhook はない。数行のコールバックで送れる |
| マーカー色の設定 | 未対応だけをピンで表示。任意の色は選べない | △ | |
| コピー・送信時の自動消去 | なし | － | ファイルとステータスで管理するため、消去ではなく「解決済み」で扱う |
| 批評モード・自動修正モード | 専用スキルはない。ブラウザ操作できるエージェントならツールバーでコメントを作れる | △ | |
| 動画の録画 | なし | － | 対象外 |

## 3. プロダクト評価

### 強み

- **証跡が残る。** コメント・対象情報・画像が `.needmark/feedback` にファイルとして残り、Git で共有できます。Agentation は既定でブラウザに 7 日しか残らず、画像もありません。
- **AI が実物を見られる。** スクリーンショットを MCP の画像として直接渡せます。「どのボタンか」を推測させずに済みます。
- **導入の自由度。** React に依存せず、Vite プラグインまたはプロキシで Next.js などにも入ります。アプリのコードを書き換えません。
- **安全側の設計。** トークンと Origin チェックつきのローカル API、本番ビルドからの除外、パスワードのマスク、コメントを命令として扱わない指示文。
- **細かい再現性。** iframe・Shadow DOM・モーダル内の選択、撮影中の変化検出、ピンの追従。

### 弱み・リスク

- **見た目が古く、ブランドからも外れていた。** 文字と記号（◉・Ⅱ）が混在したツールバーと、緑・朱色の独自配色でした。今回、アイコンとツールチップのツールボックスに作り直し、NeedBack のトークンに合わせました。
- **最初の一歩が重い。** 初回は 7 項目の設定画面が先に出ます。今回「既定のまま始める」を追加しました。
- **保存のたびに一覧が開く。** 連続してコメントしたいときに手数が増えます。保存後は一覧を開かずに次の選択へ戻るようにしました。
- **ドキュメントが仕様の網羅に寄っている。** アーキテクチャ文書は正確ですが長く、入門者には重い。利用者向けの説明は「はじめに」に寄せています。

### 評価（5段階）

| 観点 | 評価 | 理由 |
| --- | --- | --- |
| コメントの正確さ | 5 | ソース位置・識別子・画像・撮影時の検証がそろっている |
| AI への受け渡し | 4 | ファイル・CLI・MCP・コールバックに対応。Webhook URL がない |
| 操作のしやすさ | 4 | 今回の改善で初回・連続入力・説明表示を補った。ショートカットは Agentation より 1 キー多い |
| 導入のしやすさ | 4 | `pnpm add -D needmark` と `init` で始められる。Vite 設定へのプラグイン追加は手作業 |
| 継続運用 | 5 | ファイルと Git、ステータス、返信 |

## 4. UXの設計判断

NeedMarkの中心は「場所を指して、意図を残し、AIに渡す」です。利用者が覚えることを減らす方針で整理しました。

| 以前 | 課題 | 現在 |
| --- | --- | --- |
| 「選択方法」メニューで要素・テキスト・複数・配置案・移動案を切り替える | 何が選べるのか分かりにくい。要素モードでもドラッグやShiftで範囲・複数を選べ、モードの違いが曖昧 | 「コメント」（＋アイコン）1つの道具に統合。クリック＝要素、ドラッグ＝範囲、Shift＝複数、Ctrl/Cmd＝奥の要素、Alt/Option＋ドラッグ＝文字。選択中は操作の一覧を表示する |
| テキストモード | 文字以外も選べ、使い分ける場面が想像できない | Alt/Option＋ドラッグに限定。ページで文字を選んでから始めた場合は「選択中の文字にコメント」で、選んだ文字にそのままコメントできる |
| 複数モード | Shiftとの関係が分かりにくい | Shift＋クリック・ドラッグで開始し、以降はShiftなしで追加・解除 |
| 配置案・移動案が選択方法の中にある | コメントとは性質が違い、文章では伝えにくい配置の提案のための道具 | レイアウト案は機能から外した |
| 一時停止のボタン | 何が止まるのか、止まっているのかが分からない | ツールチップで目的を説明し、停止中はボタンが再生アイコンに変わる。たたんだツールバーでも停止中は表示を残す |
| 右下のツールバー | 説明がなく、常に全ツールが並ぶ | 画面下部の中央に置き、たためるようにした。ツールチップに「何ができるか」を1行添える |

## 5. 実装とドキュメントの確認で見つけた課題

| 課題 | 対応 |
| --- | --- |
| `docs/architecture.md` に「Agentation MCP プロトコル互換ではない」とだけあり、MCP 連携がない | `needmark mcp` を追加し、文書を更新（AFS とのフィールド対応も記載） |
| 初回の「コメントする」で設定画面が必ず開き、すぐに選べない | 「既定のまま始める」を追加 |
| 保存後に毎回一覧が開く | 「保存して次へ」を追加 |
| ツールバーの記号ボタンの意味とショートカットが画面で分からず、配色も NeedBack ブランドから外れている | アイコンとツールチップのツールボックスに作り直し、NeedBack のデザイントークンに配色を統一 |
| コメント入力中に対象の枠が消え、どこへのコメントか見失いやすい | 入力中も対象の枠を表示 |
| コメントの種類・重要度を伝える手段がない | 種類・重要度を追加 |
| AGENTS.md に作業手順・検証手順がなく、ドキュメント先行の運用が明文化されていない | AGENTS.md をプロジェクト共通ルールとして整理し、テストと手動確認は `docs/testing.md`、コードコメントの規約は `code-comments` スキルに分離 |
| 保存画像に描き込む対象の枠がオレンジで、画面上の青い選択枠やブランドと食い違う | 画像の枠も NeedBack の青（`#1965e3`）に統一 |
| （実装中に発見）種類・重要度のセレクトで Enter を押すと、ブラウザの暗黙送信でコメントが保存されてしまう | セレクト上の Enter では送信しないよう修正し、E2E で確認 |
| 設定画面のショートカット説明が Shift+C/P/H のままで、追加したキーが分からない | 説明を Shift+C/P/H と Ctrl/Cmd+Shift+F に更新 |

## 6. 検証結果（2026-10-07）

- 自動テスト：型チェック、ユニットテスト、ビルド、E2E（Chromium と WebKit）。種類・重要度と MCP のユニットテスト、新しい操作フローの E2E（`tests/review-flow.spec.ts`）を追加しました。
- 実操作：アイコンのツールバーとツールチップ、ライト・ダークの配色、デモで初回開始、要素・複数選択、種類・重要度つきの保存、保存して次へ、編集、ショートカット、レイアウトの起動を操作し、保存された `context.json` と `comment.md` を確認しました。
- AI 連携：ビルド済みの `needmark mcp` に JSON-RPC を送り、一覧・画像つき取得・着手・返信・指示文の作成を確認しました。待ち受け中の `needmark_watch` がブラウザで追加したコメントを受け取ること、エージェントの着手がブラウザのピンに反映されることも確認しました。
